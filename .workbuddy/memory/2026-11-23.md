## 修复：Hub（初始场景）水块鼠标点击无法旋转
现象：WaterTurnHub 里 2×2 水块（HubPuzzle.Valve）左键点击无反应，键盘 WASD / R / 滚轮正常。

根因链（HubGame.cs，HUD 全部运行时构建）：
- `HandleMouse()` 用 `EventSystem.current.IsPointerOverGameObject()` 当闸门，指针下有任意 Graphic 就 return。
- 装饰层 `Ambient/WaterTint`（`Stretch()` 生成的全屏 Image）没关 `raycastTarget`，层级又高于 `Cave`(mapRoot)
  → `IsPointerOverGameObject()` 恒为 true → `hoveredValve` 恒为 null → 永不进入 `TryRotateValve`。
- 次因：`promptGroup` / `toastGroup` 只设 alpha=0，`blocksRaycasts` 仍为 true，透明面板上下各留一条点击死区。

改动（均在 Assets/WaterTurn/HubGame.cs）：
1. `WaterTint` Image 显式 `raycastTarget = false`。
2. `promptGroup` / `toastGroup` 增加 `interactable = false; blocksRaycasts = false;`。
3. 新增 `PointerOverWidget()`：`EventSystem.RaycastAll` + `GetComponentInParent<Selectable>()`，
   只把真正可交互控件视为"挡住指针"，装饰 Graphic 一律穿透；`HandleMouse()` 改用它，
   并缓存 `PointerEventData` / `List<RaycastResult>` 避免每帧 GC。

约定：Hub 内所有纯装饰 Image / Text 必须 `raycastTarget = false`，不要再退回 `IsPointerOverGameObject()`。
待验证：Unity 重编译后进 Play，悬停水块应加亮缩放，左键旋转并提示 `SidePair`。

## 序章（初始场景）谜题设计诊断
- 明确：序章谜题 = `HubPuzzle` 的 6 个 2×2 水块（4 状态接两相邻边：北东/东南/南西/西北），不是关卡。核心动词是「接」，不是「落」。
- 关键发现 1：`HubGame.Awake` 里 `puzzle = new HubPuzzle()`，水块状态**没有写 PlayerPrefs**，每次回洞穴 6 块全部重置 → 20 关往返要重复解同一谜题约 40 次。列为高优先级修复项（持久化，或珍珠到手后把已通水块「固化」成石头）。
- 关键发现 2：`RefreshHud()` 目标文案「转动东南方向的水块，把水路接到潮汐珍珠所在的石室」直接泄题（既给方位又给动词），后续分支同样硬编码「转动水块」。
- 关键发现 3：序章「转」与关卡「转」是两套物理——序章水块自转、水在块内换位不落；关卡转房间、水往下落。同一个字两套直觉，建议序章别用「转」这个动词，并在第一关入口前加「水从缺口落下」的静态预告。
- 已认可该保留的优点：`WetSides` 湿边发光、`OpenCount` 水道 n/6 计数、`TryRotateValve` 里鱼会被水块带着转（`CanFitNext`），这三个反馈值得移植到关卡内。
- 结论：接水管只能当门槛不能当内容，序章谜题不做难度、不给失败、不教重力。
