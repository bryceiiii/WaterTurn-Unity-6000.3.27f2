## 玩法结构评估（玩核专家视角）

**用户确认的目标结构：** JellyRun 平台跳跃是独立小游戏 → 到达一颗珍珠后进入连续 5 关解谜（非"集齐 5 颗开 4 关"）→ 逐关解锁新机制作为长期驱动 → 通关后回到探索。

**结论：这是成立的"探索 + 章节入口"结构（对标《奥德赛》月亮 /《Baba Is You》），我最初"两个玩法硬拼"的判断已被澄清推翻。**
- 统一上层动词 = 探索 / 发现，珍珠是章节入口而非计数门槛。
- 高优先级三条：① 珍珠点要"看得见但够不着"，让抵达路径本身有决策；② 5 关节奏 = 1-2 引入新机制 / 3-4 组合旧机制 / 第 5 关综合考验 + 明确收尾；③ 通关后 JellyRun 要有可见变化（新通路），否则循环空转。
- 珍珠点视觉必须与章节机制绑定（每颗珍珠 = 一个机制族），否则两段仍是割裂的。

**项目约束补充：** 项目未使用 Tilemap（场景无 Grid，地板走 uGUI Image + RectTransform，关卡真源是 `LevelDefinition.rows` ASCII，`LevelSceneTools.cs:67-86,140-151` 靠子物体名/位置反推网格）。不建议引入 Tilemap——会破坏场景↔数据双向同步工具链。

## JellyRun 平台换用手绘素材（underwater-diving-files）

**素材位置：** `Assets/Resources/ManualArt/underwater-diving-files/underwater-diving-files/PNG/environment/tiles.png`（480x656，spriteMode 2，22 个切片 tiles_0..21）。关键切片：`tiles_6` = 178x70 宽苔藓石台（顶面可走）；`tiles_19` = 183x190 挂链浮空岩台（顶部浮萍 + 锥形岩体 + 铁链），用户点名用它做平台。

**新增 `Assets/WaterTurn/JellyRunTiles.cs`：** 静态访问器。`Ready` / `Get(index)`（`Resources.LoadAll<Sprite>`，切片是资产子对象，不需要像 JellyRunArt 那样重置静态缓存）/ `TopWindow(index, width, depth, phase)`（按 textureRect 子矩形 + pivot(0,1) 生成窗口 sprite，phase 用于横向滑动取样，key 含 cut/height/phaseStep 做缓存）。

**`JellyRunLedgeView`（入口石台，5 处）：** RectTransform 只有 120~190 x 16（就是碰撞盒，`JellyRunData.EntrancePlatforms`），所以美术挂在子节点 `Art` 上：tiles_19 原尺寸直接铺，顶边对齐石台线，宽度超过 183 时才轻微拉伸。

**`JellyRunFloorView`（19 段地面/岩台）：** 本体保留程序生成 sprite（深色实心岩体），顶面加 20px 苔藓岩带：以 `tiles_6` 整宽为一段，逐段铺满（`Surface 0..n`），**奇数段水平镜像**（`localScale.x = -1`，anchoredPosition.x 补 +(width)，因为 pivot 在左侧）——整宽段无法靠 phase 滑动错开，镜像才能打断"盖章式重复"。天花板（`ceiling=true`）锚到左下、`anchoredPosition.y = SurfaceDepth`、`localScale.y = -1`，让苔藓面朝下。

**踩过的坑（重要）：**
- 一开始把 tiles_6 整块 70px 高挂在入口石台下方 → 直接盖住神殿珍珠，且矩形边缘像贴纸。查层级才知道 `Glow` 顶端在 y=+3，**石台下方基本没有可用空间**，薄条（16~20px）才是对的。
- `Refresh()` 在 `Awake`（`JellyRunGame.BindSceneWorld` 里调）创建子节点会刷 `SendMessage cannot be called during Awake...` 警告。改为 `booted/queued` 延后到第一帧 `LateUpdate` 再建，`Refresh()` 仍是同步公开接口（场景烘焙工具在调）。
- 运行期节点带 `HideFlags.DontSave` 时 `DestroyImmediate` 会静默失败 → 先 `hideFlags = None` 再 `Destroy`（播放中）/`DestroyImmediate(, true)`（编辑器）。
- 旧的 "Moss" 子节点残留是上一版设计遗留，`EnsureMoss` 用 `transform.Find` 只删一个不够，改成**倒序遍历所有同名子节点**逐一判定。
- `manage_camera` 截图在编辑器失焦/暂停渲染时会返回上一帧（md5 相同），所以定位靠代码探测 + 少量截图，别靠连续截图对比。

## JellyRun 平台改用 Pixel-16px Underwater 素材 + 海底装饰

**素材：** `Assets/Resources/ManualArt/Pixel-16px Underwater/Pixel-16px Underwater/tileset/tileset.png`，208x48 单图（非切图）。导入设置为 Sprite/Single、Point、Uncompressed、PPU 16（否则默认 Bilinear+压缩会把像素画糊掉）。关键矩形（y 从图顶算）：地面块 x0..47 y0..47，其中**沙层** x5 y17 w38 h11、**土层** x6 y28 w36 h20；装饰物 17 个（贝壳 50,2,13,14 / 海带 81,1,14,47 / 珊瑚 65,2 / 96,2 / 112,2 / 鱼骨 128,16,32,15 / 岩石 160,17,32,15、128,33,64,15 / 骨 161,1 / 水晶 177,6 / 海螺 192,17,16,15 …）。

**`JellyRunTiles` 重写：** 直接 `Resources.Load<Texture2D>` 后 `Sprite.Create` 现切（`Window()` 带 cut/height/phase 缓存），不再依赖 meta 切图。新增 `Span()`（每段取 2/3~整块的伪随机宽度）和 `Phase()`——固定宽度会让长地面出现肉眼可见的周期，这是上一版苔藓带最大的毛病。`Scale = 2`（整数倍，不糊）。

**`JellyRunFloorView`：** 顶面 22px 沙层 + 1 行 40px 土层；`BandRows` 是 **const**，不是 Inspector 字段——这些 view 由 `JellyRunLevelBoard` 运行时烘焙、带 DontSave，根本不序列化，字段改了也不会生效（这次踩到了：改了默认值仍读到 2，最后发现磁盘场景里压根没有这些组件）。天花板（ceiling）锚到左下、`scale.y = -1`、`anchoredPosition.y = y + height`，沙层贴在底面。

**`JellyRunLedgeView`：** 入口石台只铺沙层（22px），**不要土层**——神殿 `Glow` 顶端在 y=+3，石台下方几乎没空间，任何厚度都会盖住珍珠和光环。

**新增 `JellyRunDeco`：** 静态 `Build(world)`，在 `JellyRunGame.Start()` 调（Awake 里建 Canvas 子节点会刷 `SendMessage cannot be called during Awake`）。沿每段 Floor 顶边撒 1~6 个装饰（高度>2倍宽判定为竖井跳过；ledge/Spawn/Portal/Switch/Valve 118px 内避开，撞到就平移重试）。容器 `Deco` 放在 sibling=floorCount，画在地面之上、果冻与鱼之下。整体 48 个。

**调试坑（重要）：** 编辑器失焦后 play loop 会**完全停住**（`Time.frameCount` 卡在 1、`Time.time` 为 0），`QueuePlayerLoopUpdate` 无效。解决：`Application.runInBackground = true`。另外 `SnapCamera` + 反射改 `fishPos` 会被物理/重生逻辑拉回出生点，要看远处画面就 `gm.enabled = false` 后直接改 `World.anchoredPosition = (-camX, camY)`（cam=(x,y) ↔ anchored=(-x, y)）。
