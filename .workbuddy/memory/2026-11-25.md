## 07/08 重做：换掉推箱，改成「单向阀」与「时效闸门」

### 起因
07/08 原来是「重压格推箱」和「两箱分工」，机制、线索、解法都与 06 高度重合。要求：两关各自独立核心机制、多步骤推理、房间形状不同。

### 选择过的机制（含否决理由）
- **排水口 'o'**（水落到即永久消失）：实现完了又否决——现有规则下鱼能游到任何相邻水格，排水只会削弱自己、几乎做不出「必须排水」的谜题。代码留在模拟器里备用。
- **单向阀 '^' '>' 'v' '<'**（采用）：水只能顺箭头进，逆着当墙。关键性质——箭头存**房间坐标**方向，房间转一次箭头跟着转 90°，所以 `arrow + turn ≡ 重力方向 (mod 4)`；对 `^`/`v` 才有解，横向箭头在此规则下恒挡（可作纯墙用）。
  - `^` 阀只在 turn=1/3（横向重力）顺流，`v` 阀只在 turn=0/2（纵向重力）顺流。
- **时效感应格 's'**（采用）：水压住才开、离开即关。语义必须是「落定开始时门开着，水就穿过去了，之后关门收不回来」。

### 落地改动
- `Puzzle.cs`：`Level.Latch`（'s'）、`HasValve`、`ArrowBlocks()`；`Fall` 改成最多三趟重落 + `Block.Arrow`。
  - 时效分支：落定后被压住且门原本关 → 开门 `continue` 重落一次；否则 `gate = pressed; break`（**不重落**，否则会把已穿门的水拉回来——第一版就是这么错的）。
- `Campaign.cs`：07 换成 9×9 竖塔单向阀，08 换成 11×7 横向双腔室 + 时效闸门；章节名改 `02 / 塞与阀`。
- `WaterGame.cs`：单向阀 = 深色方槽 + 青色箭头（`RectTransform` 按 dir 旋转 0/-90/180/90）；时效格 = 琥珀菱形，压住转青（`latchImages/latchCells`）。
- 重建 05–08 场景（builder 是数据驱动的，支持任意尺寸）。

### 教训
- 排水/减量类机制在「鱼可在相邻水格自由游动」的规则下很难承重，做减法不如做「方向/时序」约束。
- 出现「绕一圈就通关」的搜索解，通常说明机制没承重：解法全程 `gate=关` 就是信号。必须加「机制换墙后无解」的筛选。
- 手绘盘面在四向重力下极易算错，一律先跑模拟器再落地。

### 修复：单向阀对鱼生效（07 侧向穿阀 bug）
- 现象：鱼可以从侧面直接游进 `^` / `v` 格，阀只拦水不拦鱼。
- 原因：`Puzzle.Apply` 的游动分支只查墙 / 水 / 栅栏，没调 `ArrowBlocks`；当初把它当「鱼主动游、水被动流」的有意设计，实测是坏手感。
- 改法：`Puzzle.cs` 游动分支加 `ArrowBlocks(level, step, direction, p.Turn)` → `Block.Arrow`，`ApplyLethal` 同步；`WaterGame.cs` 加对应提示「单向阀只放行顺着箭头的方向」。`AgentScripts/wt_ch78.py` 的 `apply` 同步（返回 `"valve"`），否则模拟器与游戏不一致。
- 关键点：**水带鱼穿过阀格仍然允许**（那是 Fall 的路径，不经过 Apply）。07 解法 `552254` 最后一步 `fish 19→21` 正是水把鱼送进 `^` 格，所以修复后 07 仍 4转/2步、227 局面、可通关。
- 验证：Play 模式初始向右（鱼67→68 是 `v`）被挡、提示正确、鱼不动；21 关全量可解。
- 未处理：`>` `<` 四个朝向下恒挡（`(1+turn)%4 == (6-turn)%4` 无整数解），目前是纯墙，README 已标注。

### 修复：阀格不能存水（转向后水卡在阀门里）
- 现象：水顺着箭头进了阀格，转房间后箭头方向变了，水却还留在阀格里 → 看着像「没顺着方向的水也盖住了阀门」。
- 排查：BFS 枚举 07 全部 18080 个可达局面，统计阀格水位：`^`(21) 在 turn2 有 480 个、`v`(68) 在 turn1 有 384 个属于违规。
- 改法：`Puzzle.Fall` 收尾加 `eject_from_valves` 逻辑——落定后若某格水停在阀里且当前朝向不允许，就退回入口侧（`direction+2`），入口被别的水占了就从两侧（`direction±1`）挤出去，且不许连环跳进另一扇阀。`AgentScripts/wt_ch78.py` 加同名函数同步。
- 结果：违规局面 0；`^` 只在 turn1 有水、`v` 只在 turn0 有水；07 仍 `552254`、4转2步、通关，21 关全解。
- 视觉坑：`Mechanisms` 层原本在水之前，水停进阀格会把箭头整个盖住（用户截图里的「水覆盖阀门」）。新增 `valveLayer` 单独挂在最后一片水之后，箭头浮在水面上；门/重压格/时效格仍留在水下，避免箱子塞门时被门框盖住。
- 调试教训：截动画中间帧会看到「阀和鱼错位」，那是 `Paint` 的 lerp 与 room 旋转插值不同步，不代表坐标错；判定要用 `busy=false` 之后的 world position 比对。

### 修复：单向阀判定混用了两套坐标系（07 侧向穿阀的真凶）
- 现象（用户截图）：画着 `→` 的阀会放行「向屏幕下方流」的水，看着像水从阀的侧面钻进去；同一关里左箭头右箭头行为还不一样。
- 根因：`ArrowBlocks` 写成 `(arrow + turn) % 4 != direction`。`direction` 是**房间坐标**（`(move - turn + 4) % 4`，水是 `(6 - turn) % 4`），而箭头也是房间坐标（箭头是 `geometry` 的子物体，随房间 `-turn*90` 一起转）。多折算一次 `turn` 等于把箭头当成「屏幕固定方向」——判定和画面各说各话。
- 改法：`arrow != direction`，`ArrowBlocks` 去掉 `turn` 参数（4 处调用同步）；`AgentScripts/wt_ch78.py` 的 `arrow_ok` 同步。
- 正确语义（一句话）：水每个朝向只有一条流动方向，所以一扇阀只在「箭头正好朝下那一档」通水 —— `v`=0 转、`>`=1 转、`^`=2 转、`<`=3 转，其余三档就是墙。因此 `>` `<` 现在真的可用（旧 README「只有 ^ v 可用」作废）。反过来也说明一扇关着的阀可以当**假地板**用。
- 连带：旧 07 盘面是靠这个 bug 才能解（`552254` 最后一步是「向左穿 `^`」），修正后旧盘面变成 6 转乱转且不承重（去掉阀仍可解），必须重画。
- 新 07 盘面（9×9，U 形井）：
  `######### / #####E### / #####.### / #...~P..# / #.###^### / #.###.### / #.###.### / #.....#.# / #########`
  题眼：开局水停在 `^` 井盖上（阀此时是地板），要「左转甩到左井 → 下坠 → 右转贴底槽滑到阀正下方 → 再转一次顺箭头顶到出口」。par 4 转 1 步、32 局面、首步唯一；阀换墙无解、阀换地板变成 2 转捷径（说明它是地板+门双重身份）；80 个可达局面里水停阀格 0。
- 验证：21 关 `Puzzle.Begin + Solve` 全解；`Level_05..08` 用菜单重建；Play 模式手动走 `← Q R R R`，turn/fish 逐帧核对（31→64→68→14）最后 `won=True`。
- 新增 `AgentScripts/wt_07.py`：盘面体检台（par / 局面数 / 阀换墙 / 阀换地板 / 阀格水位违规）。
